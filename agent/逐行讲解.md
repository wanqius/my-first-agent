## 先看全局：37 行分成 5 块

| 块         | 行号    | 作用            | 一句话                     |
| --------- | ----- | ------------- | ----------------------- |
| **A 准备**  | 1~7   | 借工具箱          | 把要用的三个工具箱搬进来            |
| **B 工具①** | 9~10  | `get_today()` | 查今天日期——这是 Agent 的"手"    |
| **C 通讯器** | 12~19 | `ask()`       | 把对话发给模型、把回答取回来          |
| **D 记录本** | 21~24 | `messages`    | 记着"谁说了什么"，每次整本发过去       |
| **E 循环**  | 26~35 | `for`         | 想 → 做 → 看 → 够了吗，最多转 3 圈 |

**最重要的一句话（初学者最常误解）**：

> **`def` 只是"把活打包"，它本身不执行。**  
> 程序从上往下走，走过 `def` 时只是"记下这个工具"，一直到最后那个 `for` 循环，才真正开始干活。

# 块 A · 准备（第 1~7 行）

```python
# 会自己多步干活的助手（阶段 3）
# 这个文件从零开始，一段一段加。
# 今天的目标：让它学会"自己判断要不要再查一次"。

import os
import requests
import datetime
```

| 行   | 代码                | 干嘛的      | 大白话                         |
| --- | ----------------- | -------- | --------------------------- |
| 1~3 | `# ...`           | 注释       | 以 `#` 开头的行，**程序完全忽略**，只写给人看 |
| 5   | `import os`       | 借"系统工具箱" | 这个文件里只用它一件事：读环境变量里的 API Key |
| 6   | `import requests` | 借"上网工具箱" | 用它发 HTTP 请求给 DeepSeek       |
| 7   | `import datetime` | 借"日期工具箱" | 用它拿到"今天几号"                  |

**为什么要在最上面 import**：Python 规定"先借工具，后使用"。放在文件顶部是行业习惯，也方便一眼看出这个程序依赖什么。

> 常见错误：把 `import` 写在函数里面也能跑，但每次调用都要重新借一次，还容易看漏。**统一放顶部。**

# 块 B · 工具①：查今天日期（第 9~10 行）

```python
def get_today():
    return datetime.date.today().isoformat()
```

### 第 9 行：`def get_today():`

| 部分          | 含义                                       |
| ----------- | ---------------------------------------- |
| `def`       | **define（定义）**——"我要打包一段活"                |
| `get_today` | 给这段活起的名字（你自己起的，叫 `get_today` 是因为它"获取今天"） |
| `()`        | 括号里放**参数**。这里是空的 = **不需要你给任何东西**，它自己就能干活 |
| `:`         | 冒号 = "下面缩进的部分，都属于我"                      |

**这行只是"登记"，不执行。** 就像给一个工具贴上标签放进工具箱，还没人用它。

### 第 10 行：`return datetime.date.today().isoformat()`

这行是连在一起的三步，从里往外读：

| 步骤 | 代码片段                    | 结果                                                |
| -- | ----------------------- | ------------------------------------------------- |
| ①  | `datetime.date.today()` | 拿到"今天"这个日期对象（内部长这样：`datetime.date(2026, 10, 29)`） |
| ②  | `.isoformat()`          | 把它转成标准字符串：`"2026-10-29"`                          |
| ③  | `return`                | **把结果交出去**——谁喊我，我就把这个字符串给他                        |

**为什么要转成字符串**：因为后面要拼进一句话里（`"今天是 " + 日期`），字符串才能拼。

**`return` 和 `print` 的区别（很多人搞混）**：

|            | 干什么      | 结果去哪           |
| ---------- | -------- | -------------- |
| `print(x)` | 显示在屏幕上   | **只给人看，程序拿不到** |
| `return x` | 把值交回给调用者 | **程序能接着用**     |

> 一句话：`print` 是"喊出来"，`return` 是"递过去"。**工具必须用 `return`，不然别人拿不到结果。**

# 块 C · 通讯器：ask()（第 12~19 行）

```python
def ask(messages):
    r = requests.post(
        "https://api.deepseek.com/chat/completions",
        headers={"Authorization": "Bearer " + os.environ.get("DEEPSEEK_API_KEY", "")},
        json={"model": "deepseek-chat", "messages": messages, "temperature": 0},
        timeout=30,
    )
    return r.json()["choices"][0]["message"]["content"]
```

### 第 12 行：`def ask(messages):`

| 部分           | 含义                      |
| ------------ | ----------------------- |
| `def ask`    | 定义工具，名字叫 `ask`（问）       |
| `(messages)` | **需要一个参数**：把"整本对话记录"交给它 |

**为什么要有参数**：因为每次要问的内容不一样。参数 = **同一套动作，喂不同的料**。

### 第 13 行：`r = requests.post(`

`requests.post(...)` = **向某个网址发一份数据，并等它回复**。  
返回值（模型的原始回信）装进变量 `r`。

> `post` 和 `get` 的区别先不用管，记住：**发给 AI 说话用 `post`**。

### 第 14 行：`"https://api.deepseek.com/chat/completions",`

**信封上的地址**——DeepSeek 的"对话服务"窗口。换厂商就要换这个地址。

- `api.deepseek.com` = 服务器
- `/chat/completions` = 具体窗口（对话补全）

### 第 15 行：`headers={"Authorization": "Bearer " + os.environ.get("DEEPSEEK_API_KEY", "")},`

**信封上贴的通行证**，证明"是我本人，别拒我"。

拆开看：

| 片段                                       | 含义                                                |
| ---------------------------------------- | ------------------------------------------------- |
| `"Authorization"`                        | 请求头的名字，意思是"授权"                                    |
| `"Bearer "`                              | 固定格式（Bearer = 持有者），注意**后面有一个空格**，不能少              |
| `os.environ.get("DEEPSEEK_API_KEY", "")` | 从**环境变量**里读出 Key；第二个参数 `""` 是"读不到就用空字符串"（这样不会直接崩） |
| 最外层 `+`                                  | 把 `"Bearer "` 和 Key 拼成 `Bearer sk-xxxx`           |

> **为什么 Key 不直接写死在代码里**：代码一旦上传 GitHub 或发给别人，Key 就泄露了，别人能刷你的额度。**环境变量是唯一正确做法。**

### 第 16 行：`json={"model": "deepseek-chat", "messages": messages, "temperature": 0},`

**信纸的内容**，三个键：

| 键               | 值                 | 含义                                |
| --------------- | ----------------- | --------------------------------- |
| `"model"`       | `"deepseek-chat"` | 用哪个模型（DeepSeek 有几款，chat 是最通用的）    |
| `"messages"`    | `messages`        | **把整本对话记录原样送过去**——这是全程序最关键的一处     |
| `"temperature"` | `0`               | 温度=0：输出尽量稳定、不随机。做工具判断时要"稳定"不要"创意" |

> 注意这里的 `messages` 没有引号——它引用的是**外面传进来的那个变量**，不是字符串 `"messages"`。少写引号是引用变量，多写引号就变成文字了。

### 第 17 行：`timeout=30,`

**最多等 30 秒**。超时就报错，不会一直卡着。

> 不写 `timeout` 的话，网络不通时程序可能永久卡死。**这是生产代码的必备项。**

### 第 18 行：`)`

括号收尾，`requests.post(...)` 这一整段结束。

### 第 19 行：`return r.json()["choices"][0]["message"]["content"]`

**剥洋葱**——模型回信是一大坨结构化数据，要一层层剥：

| 层级            | 剥出什么                 | 大白话         |
| ------------- | -------------------- | ----------- |
| `r.json()`    | 把回信文字变成"可查询的数据"      | 拆信封         |
| `["choices"]` | 里面装着"所有候选回复"（通常 1 个） | 翻到"备选答案"那叠纸 |
| `[0]`         | 取第 0 个（第一个）          | 拿最上面那张      |
| `["message"]` | 这张纸里的"消息"部分          | 找到"消息"栏     |
| `["content"]` | 消息里的**正文文字**         | 读出正文        |
| `return`      | 交出去                  | 把答案递给喊它的人   |

> 这一串结构在 OpenAI / 千问 / 豆包 都一样，**换模型厂商基本不用改**。

# 块 D · 记录本：messages（第 21~24 行）

```python
messages = [
    {"role": "system", "content": "你是一个助手。如果回答需要知道今天的日期，就只回复四个字：NEED_DATE，不要多说。否则直接回答。"},
    {"role": "user", "content": "用一句话鼓励我"},
]
```

### 第 21 行：`messages = [`

创建一个**列表**（一排格子），起名 `messages`。列表用 `[ ]` 包起来，里面可以放很多条。

### 第 22 行：`{"role": "system", "content": "..."},`

**第一条：给模型立的规矩。**

| 键           | 值          | 含义                          |
| ----------- | ---------- | --------------------------- |
| `"role"`    | `"system"` | 身份 = **系统**（设定了就一直生效，优先级最高） |
| `"content"` | 那段话        | 规矩的具体内容                     |

这段话拆开看，其实说了两件事：

| 规矩                             | 作用                               |
| ------------------------------ | -------------------------------- |
| "需要知道日期 → 只回复 `NEED_DATE` 四个字" | **告诉它"缺信息时该怎么喊"**——这就是最原始的工具调用协议 |
| "否则直接回答"                       | 让它在该直接答的时候别废话                    |

> **重要对应**：这条 `system`，就是你在阶段 1 扣子里填的「人设与回复逻辑」。**平台替你拼进去了，代码把它露出来了。**

### 第 23 行：`{"role": "user", "content": "用一句话鼓励我"},`

**第二条：用户说的话。** `role: user` = 用户。

> 这行就是你要换的地方。换成 `"今天星期几？"`，它就会去查日期。

### 第 24 行：`]`

列表结束。

### 为什么"两条消息"要一起发

因为**大模型没有记忆**。它每次都是"第一次见你"，所以必须把"规矩"和"问题"一起塞给它。

# 块 E · 循环：想 → 做 → 看（第 26~35 行）

```python
for step in range(1, 4):
    reply = ask(messages)
    print("[第", step, "轮] 模型：", reply)

    if reply.strip() == "NEED_DATE":
        messages.append({"role": "assistant", "content": reply})
        messages.append({"role": "user", "content": "今天是 " + get_today() + "，请回答。"})
    else:
        print("最终回答：", reply)
        break
```

### 第 26 行：`for step in range(1, 4):`

| 部分                | 含义                                   |
| ----------------- | ------------------------------------ |
| `for ... in ...:` | "把后面那串值，一个个取出来，每个都执行一遍下面的代码"         |
| `step`            | 变量名，每轮换一个值（第几轮）                      |
| `range(1, 4)`     | 生成 `1, 2, 3`——**到 4 之前停，不含 4**（左闭右开） |

**所以这句的意思是：转 3 圈，`step` 分别是 1、2、3。**

> 为什么上限是 3？**防止它停不下来**。这是"停止条件"的第一道保险——即使模型疯了，最多也只转 3 圈。

### 第 27 行：`reply = ask(messages)`

**喊通讯器干活**：把整本记录本交过去，拿回来的回答装进 `reply`。

**这一行就是循环里的"想"**——模型看完记录，决定下一步说什么。

### 第 28 行：`print("[第", step, "轮] 模型：", reply)`

打印日志。`print` 后面用**逗号**隔开多个东西，会自动拼成一句（逗号处会补一个空格）。

**为什么一定要打日志**：不打日志，你根本看不见它在转几圈、每圈说了什么——**出问题就抓瞎**。这是"可观测性"的最小形态。

### 第 30 行：`if reply.strip() == "NEED_DATE":`

**判断它是不是在喊"我要日期"。**

| 部分              | 含义                                    |
| --------------- | ------------------------------------- |
| `reply.strip()` | 去掉前后空格和换行。**模型有时会多打一个空格或换行**，不去掉就判断失败 |
| `==`            | "是否等于"（注意是两个等号；一个 `=` 是赋值）            |
| `"NEED_DATE"`   | 我们和模型约定的暗号                            |

**这一行是"决策点"**：是暗号 → 去干活；不是 → 说明它在回答了。

### 第 31 行：`messages.append({"role": "assistant", "content": reply})`

**把模型说的话记进记录本。**

- `.append(...)` = 往列表末尾追加一条
- `"role": "assistant"` = 标注"这是**模型**说的"

**为什么要记它说过的话**：下一轮发给模型时，它能看见"我刚才喊了 NEED_DATE"，才能理解"为什么现在有人给我日期了"。**不记，它就会一头雾水甚至重复喊。**

### 第 32 行：`messages.append({"role": "user", "content": "今天是 " + get_today() + "，请回答。"})`

**把工具查到的结果写进记录本，然后准备再问一次。**

| 部分                       | 含义                                      |
| ------------------------ | --------------------------------------- |
| `get_today()`            | **真的调用工具**——拿到 `"2026-10-29"`           |
| `"今天是 " + ... + "，请回答。"` | 拼成一句完整的话                                |
| `"role": "user"`         | **标成"用户说的"**——因为这是我们（程序）提供给它的信息，不是它自己说的 |

> **这行就是循环里的"做 + 看"**：执行工具 → 把结果喂回去。

**为什么标成 `user` 而不是 `assistant`**：`assistant` 是"模型自己说的话"，`user` 是"外界提供的信息"。工具结果属于外界，所以放 `user`。（工业界也有用 `tool` 角色的，本质一样：告诉模型"这是工具返回的"。）

### 第 33 行：`else:`

**不是 `NEED_DATE`** → 说明它已经在正常回答了。

### 第 34 行：`print("最终回答：", reply)`

把最终答案打印出来。

### 第 35 行：`break`

**跳出循环，立刻结束。**

这是"停止条件"：既然它已经回答了，就没必要再转第 2 圈、第 3 圈。

> **`break` 只有一层循环时是"跳出这一层"**。以后写多层循环要注意它只跳最近的一层。

# 运行起来，谁先谁后（时序）

很多人以为 `def` 会执行——**不会**。真实顺序是：

```text
① 三个 import          → 借工具箱（执行）
② def get_today()      → 只是登记，不执行 ← 关键
③ def ask()            → 只是登记，不执行 ← 关键
④ messages = [...]     → 创建记录本（执行）
⑤ for 第 1 轮：
     5.1 ask(messages) → 发网络请求，拿到回答
     5.2 print         → 打印"[第 1 轮] ..."
     5.3 if 判断
         ├─ 是 NEED_DATE → append 两条 → 进入第 2 轮
         └─ 否           → print 最终回答 → break → 结束
⑥ for 第 2 轮（如果没 break）：
     6.1 ask(messages) → 这次记录本里多了 2 条（模型的话 + 日期）
     6.2 ... 同上判断
```

**"记录本变厚"是关键**：第 2 轮发出去的，比第 1 轮多了两条。这就是"记忆"的全部真相。

# 删了会怎样（这张表最有用）

| 改什么                                | 会发生什么                                       | 为什么                |
| ---------------------------------- | ------------------------------------------- | ------------------ |
| 删 `import datetime`                | `NameError: name 'datetime' is not defined` | 工具箱没借就来用           |
| `get_today` 里把 `return` 改成 `print` | 拼字符串时报 `TypeError`                          | 工具交不出东西（返回 `None`） |
| 删 `headers`                        | `401 Authentication Fails`                  | 没通行证，被拒            |
| 删 `"temperature": 0`               | 回答更"飘"，同样的问法可能不同结果                          | 默认温度更高             |
| 删第 31 行（记 `assistant`）             | 模型可能**重复喊 NEED_DATE**，甚至答非所问                | 它看不见自己刚说过什么        |
| 删第 35 行 `break`                    | 转满 3 圈，最后**没有"最终回答"**                       | 没有停止条件             |
| `range(1, 4)` 改成 `range(1, 2)`     | 只转 1 圈 → 拿到 `NEED_DATE` 就结束了，永远等不到答案        | 轮次不够               |
| 第 23 行改成 `"今天星期几？"`                | 变成 2 轮，会去查日期                                | 触发了工具调用            |


> **建议你亲手试两个**：删 `break` 看它转三圈；删第 31 行看它重复喊。**亲手弄坏一次，比看十遍解释记得牢。**

# 最薄弱前提 & 未闭环项

- **最薄弱前提**：`NEED_DATE` 是本课自制的"暗号协议"，模型若不严格守约（多打标点、换个说法），判断就会失败、循环空转。真实项目必须用结构化协议。

## 二、块 A · 顶部（第 1~8 行）

```python
import os
import requests
import datetime
import json
```

| 行 | 代码                | 干嘛的                          |
| - | ----------------- | ---------------------------- |
| 5 | `import os`       | 读环境变量里的 Key                  |
| 6 | `import requests` | 发 HTTP 请求                    |
| 7 | `import datetime` | 算日期                          |
| 8 | **`import json`** | **新增**：`json.loads()` 在这个模块里 |

### `json` 是什么

一&#x79CD;**"文字格式"**——长得像 Python 的字典，但它是纯文字，人和程序都能读。

|               | 长什么样                       | 是什么                |
| ------------- | -------------------------- | ------------------ |
| JSON **文字**   | `'{"tool":"count_words"}'` | 一串字符（**纸条**）       |
| Python **字典** | `{"tool": "count_words"}`  | 可操作的数据（**读进脑子里了**） |

**两者的转换靠两个函数**：

| 函数               | 方向      | 记忆法                        |
| ---------------- | ------- | -------------------------- |
| `json.loads(文字)` | 文字 → 字典 | **l**oad **s**tring（加载字符串） |
| `json.dumps(字典)` | 字典 → 文字 | **d**ump **s**tring（倒出字符串） |

> 我们只用 `loads`：**模型给的是文字，程序要的是数据。**

## 三、块 B · 两个工具（第 11~15 行）

## 五、块 D · 提示词（第 26~36 行）—— 本课最重要的一块

```python
messages = [
    {"role":"system","content":"""你有两个工具可用：
     1.get_today()-查询今天的日期，不需要参数
     2.count_words(text)-统计一段文字有多少个字,需要参数text

     需要工具时,只输出一行JSON,不要解释:
     {"tool":"工具名","args":{"参数名":值}}

    {"role":"user","content":"今天是几号？顺便数数这句话有多少个字。"},

```

### 先说 `"""` 三引号

| 写法                | 能写几行            | 例子     |
| ----------------- | --------------- | ------ |
| `"..."` / `'...'` | **只能一行**        | `"你好"` |
| `"""..."""`       | **可以多行，换行原样保留** | 上面这一大段 |

**提示词通常很长、有换行，所以一律用三引号。**

> 注意：三引号里的 `{}` 就是普通字符，**不用转义**。（只有在 f-string 里才需要用 `{{ }}`，这里不是。）

### 这段提示词的四层结构（背下来，以后写任何提示词都用）

| 层          | 内容                           | 作用                     |
| ---------- | ---------------------------- | ---------------------- |
| **① 工具清单** | 两个工具的名字、作用、参数                | 告诉模型"你有什么手"            |
| **② 输出格式** | `{"tool":..., "args":{...}}` | 约定"要工具时怎么说话"           |
| **③ 兜底规则** | "不需要工具时，直接回答"                | 防止它什么事都去调工具            |
| **④ 硬约束**  | "只输出一行 JSON，**不要解释**"        | 防止它加 \`\`\`json 包装或客套话 |

**第 ④ 层最容易漏，但最要命**：

不写这句，模型很可能回你：

````
好的，我来帮你统计：
```json
{"tool": "count_words", "args": {"text": "今天有点累"}}
````

```

**带着"好的"和代码块围栏——`json.loads` 立刻崩。**

> 这就是提示词工程的第一性原理：**把隐含期望写成显式约束。**
> 你以为"它应该知道"，但它不知道——**它只按最可能的理解执行**。

### 工具描述为什么写得这么细

```

2.count_words(text)-统计一段文字有多少个字,需要参数text

````

三个信息缺一不可：

| 信息 | 没有会怎样 |
|---|---|
| 名字 `count_words` | 模型不知道该喊什么名字 |
| 作用"统计字数" | 模型不知道什么时候该用它 |
| 参数 `text` | 模型不知道该填什么字段名 → 你 `call["args"]["text"]` 就取不到 |

**这份描述，就是行业里的 "tool schema"（工具定义）。**
````

### 第 42 行：`if reply.strip().startswith("{"):`

**判断"这行是不是以 `{` 开头"。**

| 部分                 | 含义                                 |
| ------------------ | ---------------------------------- |
| `.strip()`         | 去掉前后空格/换行（模型有时会多打空行）               |
| `.startswith("{")` | 是不是**以某个字符开头**，返回 `True` / `False` |

**为什么不能再用 `==`？**

| 情况             | 内容会变吗                     | 能不能用 `==`           |
| -------------- | ------------------------- | ------------------- |
| 暗号 `NEED_DATE` | 每次都一样                     | ✅ 能                 |
| JSON 工具调用      | **参数每次都不同**（`text` 内容不一样） | ❌ **不能**，只能判断"长什么样" |

> **这是判断逻辑的一次升级：从"比对固定值"变成"识别格式"。**  
> 真实系统里更严谨的做法是"先试解析，解析成功就是工具调用"（`try: json.loads(...)`），第 3 课会改。

### 第 43 行：`call = json.loads(reply)`

**把 JSON 文字变成字典。**

```text
之前：'{"tool":"count_words","args":{"text":"今天有点累"}}'   ← 一整串字符
之后：{'tool': 'count_words', 'args': {'text': '今天有点累'}}   ← 可以按键取值
```

**这就是"文字 → 数据"的关键一跃。** 没有这一步，你只能干瞪眼。

### 第 44~45 行：打印它想干什么

### 第 47~50 行：工具分发（路由）

```python

    result = get_today()
elif call["tool"] == "count_words":
    result = count_words(call["args"]["text"])
```

| 行                                     | 含义                                   |
| ------------------------------------- | ------------------------------------ |
| `if call["tool"] == "get_today":`     | 它点的是"查日期" → 走这条                      |
| `result = get_today()`                | **真的执行**，结果装进 `result`               |
| `elif call["tool"] == "count_words":` | 它点的是"数字数" → 走这条                      |
| `call["args"]["text"]`                | **剥两层**：先取 `args`（是个字典），再从里面取 `text` |

**"剥两层"长这样**：

```text
call                      → {'tool': 'count_words', 'args': {'text': '今天有点累'}}
call["args"]              → {'text': '今天有点累'}
call["args"]["text"]      → '今天有点累'          ← 这才是工具要的东西
```

> **一句话：这就是"工具分发"（tool dispatch）——一个按名字分岔的路由器。**  
> 2 个工具用 `if/elif`；5 个就开始丑；20 个必须换成字典注册表 `TOOLS = {"名字": 函数}`。

打日志。**这一行是你判断"执行到底有没有发生"的唯一证据。**

| 54 | **工具的执行结果**          | 让它有信息可答          |

## 八、改一处会怎样（动手前先看表）

| 改什么                                  | 会发生什么                                                | 为什么                        |
| ------------------------------------ | ---------------------------------------------------- | -------------------------- |
| 删 `import json`                      | `NameError: name 'json' is not defined`              | 工具没借                       |
| 提示词删掉"不要解释"                          | `json.loads` 报 `JSONDecodeError`                     | 模型加了"好的"或代码块围栏             |
| 用 `==` 代替 `startswith`               | 永远匹配不上，模型的话被当成最终答案                                   | JSON 内容每次不同                |
| 删 `str(result)`                      | `TypeError: can only concatenate str`                | 文字不能加数字                    |
| 把 `elif` 那支删掉                        | 调 `count_words` 时 `result` 未定义 → `UnboundLocalError` | 路由缺了一条路                    |
| 工具名写错（`call["tool"] == "countWord"`） | 同上，`result` 未定义                                      | 名字必须与提示词里的完全一致             |
| 提示词里工具名写成 `count_word`               | 模型输出这个名字 → 你的 if 匹配不上 → 崩                            | **提示词和代码必须用同一个名字**（最容易犯的错） |

1. **把提示词里"不要解释"删掉** → 看它怎么把 JSON 包起来 → 你亲眼见到 `JSONDecodeError`
2. **把提示词里 `count_words` 改成 `count_word`** → 看程序怎么崩

## 九、你手写的 vs 行业标准

| 你写的                          | 行业叫法                                  | 差异                         |
| ---------------------------- | ------------------------------------- | -------------------------- |
| 提示词里那段工具说明                   | **tool schema / function definition** | 真实 API 用结构化 JSON 传，不写在提示词里 |
| `{"tool": ..., "args": ...}` | **tool_calls**                        | 真实 API 由模型返回结构化字段，不用自己解析文字 |
| `if/elif` 分发                 | **tool dispatch / tool router**       | 真实项目用注册表字典                 |

| `break`                      | **stop condition**                    | 一致 ✅                       |

**结论**：结构完全一致，只是"协议"是我们手写的简化版。

## 二、第 38 行：`last_call=""`

```python
last_call=""
```

**在 `for` 循环外面**，准备一个"上一圈干了什么"的记录，初始是空的。

**为什么必须放在循环外面**：放在里面就每圈都清空一次，永远比不出"跟上一圈一样"。

> 这类变量有个名字：**循环外的状态（state）**。它的寿命比循环的一轮长，用来"记住跨轮次的信息"。

## 三、第 45~50 行：给 JSON 加保护

```python
        try:
            call = json.loads(reply)
        except Exception as e:
            print("   ⚠ JSON 解析失败：", e)
            print("   ⚠ 原始输出：", reply)
            break
```

### 逐行

| 行  | 代码                         | 说明                                |
| -- | -------------------------- | --------------------------------- |
| 45 | `try:`                     | 开始"可能出事"的区域                       |
| 46 | `call = json.loads(reply)` | **唯一可能抛异常的一行**                    |
| 47 | `except Exception as e:`   | 接住**普通错误总父类**下的所有异常               |
| 48 | `print("⚠ JSON 解析失败：", e)` | 说清原因（如 `Expecting ',' delimiter`） |
| 49 | `print("⚠ 原始输出：", reply)`  | **把模型原话打出来**——排查时最有用的一行           |
| 50 | `break`                    | 停。同样的输入大概会得到同样的坏输出，重试是浪费钱         |

### 为什么 `try` 只包这一行，不包整个循环

| 写法                    | 后果                  |
| --------------------- | ------------------- |
| 只包 `json.loads`（现在这样） | 出错时**精确知道是哪一步**：解析  |
| 包住整个 `for` 循环体        | 所有错误混在一起，日志看不出走到哪一步 |

> 原则：**`try` 的范围越小越好，只包"真正会出意外的那几行"。**

### 为什么写 `Exception` 而不是留空

```python
except Exception as e:   # ✅ 只接普通错误
except:                  # ❌ 连 Ctrl+C、程序退出都接
```

`KeyboardInterrupt`（你按 Ctrl+C）**不在 `Exception` 底下**，而在更上层的 `BaseException`。

**这是救命设计**：如果裸 `except` 把 Ctrl+C 也吞了，你就永远停不下来一个死循环——只能拔电源。

### 报错那一刻，`try` 里剩下的行不执行

```text
try:
    A   ← 执行
    B   ← 这里报错
    C   ← 永远不执行
except:
    D   ← 跳到这里
E       ← 继续
```

所以 `try` 里不要塞一长串流程。

## 四、第 55~60 行：重复检测（指纹）

### 逐行

| 行  | 代码                                         | 说明                       |
| -- | ------------------------------------------ | ------------------------ |
| 55 | `signature=call["tool"]+str(call["args"])` | **算指纹**：工具名 + 参数字符串，拼成一串 |
| 57 | `if signature==last_call:`                 | 跟上一圈比，**完全一样 = 原地打转**    |
| 58 | `print("⚠ ...")`                           | 明确告诉你"是我拦下的"，不是神秘卡住      |
| 59 | `break`                                    | 止损：不再花第 3 次钱             |
| 60 | `last_call=signature`                      | **更新记录**，供下一圈比对          |

### 为什么指纹必须含参数

| 只比工具名                | 工具名 + 参数（正确）       |
| -------------------- | ------------------ |
| 连着查两天日期 → **被误判成打转** | 参数不同 = 在干不同的事 → 放行 |
| 会杀掉正常的多步任务           | 只有**完全一样**才算打转     |

> 这就是工程里的"**幂等判断 / 去重**"：不看"动作"，看"**动作 + 输入**"。

### 顺序很重要：`last_call=signature` 必须放在 `if` 之后

如果写在 `if` 前面：

```python
last_call = signature          # ← 先更新
if signature == last_call:     # ← 永远相等！
    break
```

**第一轮就会停**，程序彻底废掉。**先比对，后更新**——这个顺序不能反。

## 五、第 62~70 行：两层兜底

```python
        if call["tool"] == "get_today":
            result = get_today()
        elif call["tool"] == "count_words":
            if "text" in call["args"]:
                result = count_words(call["args"]["text"])
            else:
                result="缺少参数 text"
        else:
            result="没有这个工具："+call["tool"]
```

### 三层结构

```text
① 是 get_today 吗？        → 是 → 直接执行（不需要参数）
② 是 count_words 吗？      → 是 → 检查参数
                              ├ 有 text → 执行
                              └ 没有   → "缺少参数 text"（不崩）
③ 都不是                   → "没有这个工具：XXX"（不崩）
```

| 代码                           | 说明                                            |
| ---------------------------- | --------------------------------------------- |
| `if "text" in call["args"]:` | **检查字典里有没有这个键**（阶段 2 用过：`if "error" in data`） |
| `else: result="缺少参数 text"`   | 缺参数不报错，**把这句话当成"结果"**                         |
| 最外层 `else:`                  | 工具名不认识，同样给一句话                                 |

### 最关键的设计：兜底不是"打印然后退出"

注意 `result` 被赋值成一句**错误说明**，然后会走原来的流程——**被 `append` 进 `messages`，喂回给模型**。

模型下一轮看到"没有这个工具：get_weather"，就会想："哦，我编错了，换个说法。"

**实测结果**：

```
[第 1 轮] → 工具返回： 没有这个工具：get_weather
[第 2 轮] 抱歉，我目前没有查询天气的工具…
```

**它自己改口了。** 如果程序直接崩，它永远没这个机会。

> 行业术语：**error observation（错误观察）**——把错误当成一次"观察结果"回喂，是 Agent 自我纠正的基础。

## 三、第 48 / 51~53 行：裁剪

```python
KEEP=4

...
    if len(messages)>KEEP+1:
        messages=messages[:1]+messages[-KEEP:]
        print("[裁剪] 太长了，只留 system + 最近", KEEP, "条")
```

| 部分                       | 说明                         |
| ------------------------ | -------------------------- |
| `KEEP=4`                 | 配置：最近保留 4 条                |
| `len(messages) > KEEP+1` | 超过"4 条 + 1 条 system"才裁     |
| `messages[:1]`           | **只要第 0 条**（system）——规矩不能丢 |
| `messages[-KEEP:]`       | **倒数 4 条到结尾**              |
| `列表A + 列表B`              | 两个列表拼成一个**新**列表            |

### 切片读法（一次记住）

```text
[ :1]   → 从头到下标 1 之前  = 只要第 0 个
[-4: ]  → 倒数第 4 个到结尾
[1:3]   → 下标 1、2（不含 3）
```

**左边不写 = 从头开始；右边不写 = 一直到结尾；负数 = 从尾巴数起。**

### 为什么必须保住 system

system 里装着"工具清单 + JSON 协议 + 记忆使用规则"。  
**规矩一丢，模型就不知道怎么说话**，整个协议当场崩——它会开始说人话，而你的程序在等 JSON。

## 六、故障复盘：上下文污染（本课最重要的一段）

### 现象（真实输出）

问题：`我最近心情怎么样？`

| 轮次 | 它做的事                                   |
| -- | -------------------------------------- |
| 1  | 调 `get_today`（勉强合理："最近"要相对今天）          |
| 2  | 调 `count_words`，把**整段历史心情**当参数，返回 66 字 |
| 3  | 回答"今天是…，共 66 字"                        |

**完全没回答心情问题。**

### 根因

记忆被塞成了 `role: "user"`：

```python
messages.insert(1, {"role": "user", "content": "这是我以前记录的心情：\n" + old})
```

`user` 的含义是"**用户说的话/要求**"。模型收到的信号是：

> "用户发给我一大段文字" + "用户问心情怎么样"  
> → **那这段文字大概是让我处理的数据吧？**

它手里正好有"数字数"的工具 → 两者一对上 → 跑偏。

### 两条修法，缺一不可

| 修法                 | 作用          |
| ------------------ | ----------- |
| **改角色**（并进 system） | 从"任务"变成"背景" |
| **加规则**（第五节那三句）    | 明确"别处理它"    |

只改角色 → 它可能仍然想"整理一下这段文字"；  
只加规则 → 位置仍是"用户消息"，信号冲突。

### 提炼成通用原则

> **上下文里的每一段文字，模型都会当回事。**  
> 塞资料必须同时说清三件事：  
> ① **这是什么**（历史记录 / 参考资料 / 用户要求）  
> ② **放在哪个角色**（system = 背景规矩 / user = 当前任务）  
> ③ **拿它干什么**（用来回答，不是用来处理）

## 一、这版改了 2 处

## 二、新增的【事实边界】三条

```text
【事实边界】
1. 只回答你确实知道的内容；不确定就明确说"我不确定"。
2. 不要编造书名、作者、数字、日期、链接这类具体信息。
3. 需要实时数据但没有对应工具时，直接说明"我没有这个能力"，并告诉用户去哪里查。
```

**每条在防什么**：

| 条 | 防的是什么失败                    |
| - | -------------------------- |
| 1 | 把"不知道"包装成"好像知道"            |
| 2 | **具体信息型幻觉**（书名/数字/链接最容易编）  |
| 3 | "没有能力却硬答"——同时给出替代方案，用户体验更好 |

### 为什么这三条要写在 system 里

- 写在 `user` 里 → 只对"这一句"有效，下一轮就忘
- 写在 `system` 里 → **每一轮都生效**，而且是"规矩"级别

> 这也是本课第 4 段学的：**角色决定权重**。

### 一个必须接受的现实

规则的作用是**降低概率**，不是**制造效果**。

测试时模型本来就不编，加了规则也看不出差别——**这不代表规则没用**，就像系安全带当天没出事故，不等于安全带无效。

## 三、`count_chars`：一个故意留下的"坏例子"

```python
def count_chars(text):
    return len(text.replace(" ", ""))
```

| 部分                      | 说明                     |
| ----------------------- | ---------------------- |
| `text.replace(" ", "")` | 把**所有空格**替换成空串（等于删掉空格） |
| `len(...)`              | 再数长度                   |

**它和 `count_words` 的区别只有一个：算不算空格。**

| 输入         | `count_words`  | `count_chars` |
| ---------- | -------------- | ------------- |
| `今天 心情 很好` | **8**（含 2 个空格） | **6**（不含）     |

### 实验结果是"它选了 count_words，报 8"

**这就是选错工具的典型现场**：

- 两个工具都能"说得通"
- 输出格式完全正常
- **你无法从结果判断它对不对**

### 为什么要把这个"坏例子"留在代码里

因为它精确展示了工业界的一条经验：

> **工具不是越多越好。每多一个，模型就多一次选错的机会。**  
> 名字相近（`count_words` / `count_chars`）、描述重叠（都叫"统计文字"）——是选错的温床。

**真实项目里的三种解法**：

1. 描述写到"能区分"为止（不是"统计字数"，而是"统计**含空格**的字符数"）
2. 名字带区分词（丑但清楚）
3. **干脆合并成一个工具，用参数控制**（最推荐）

> 未闭环项里已经记了：**该删除或合并 `count_chars`**。这是留给学习者自己动手的一次"做减法"。

| `ask()` 出口 | 1 个 | 3 个（成功 / 网络失败 / 接口报错） | 失败也是结果，交给调用方决定怎么办 |

## 二、逐段

### 第 21 行：先占位

```python
def ask(msgs):
    r = None
```

若请求本身失败，`r` 根本不存在，后面 `r.status_code` 会抛 `NameError`。先赋默认值。

### 第 27 行：按请求声明不走代理

```python
        proxies={"http": None, "https": None},
```

`None` = 该协议不使用代理。**这是"按请求选路"，不是全局开关**——以后写访问 GitHub 的工具时，那一处就不要禁用。

### 第 30~33 行：失败也要留下证据

```python
    except Exception as e:
        print("   ⚠ 网络请求失败：", type(e).__name__, str(e)[:120])
        if r is not None:
            print("   ⚠ 状态码：", r.status_code, "| 响应前 200 字：", repr(r.text[:200]))
        return None
```

- `str(e)[:120]` 截断：异常信息可能极长，日志要可读
- `repr(...)`：能把空字符串和空格区分出来（`''` vs `' '`）

### 第 34~36 行：先校验，再消费

```python
    if "error" in data:
        print("   ⚠ 接口返回错误：", data["error"].get("message", data["error"]))
        return None
```

这个模式在 `memo.py` 里写过，本文件一直没搬过来——所以 Key 失效时会去翻 `data["choices"]`，直接 `KeyError`。

### 主循环 3 行：把失败当成一种结果

```python
    if reply is None:
        print("⚠ 本轮调用失败，任务中止。")
        break
```

为什么用 `None` 而不是 `""`：空字符串可能是模型真的返回了空内容；`None` 明确表示"压根没拿到"。

## 三、为什么 `try` 不包到最后一行

如果把 `return data["choices"][0]["message"]["content"]` 也包进 `try`，
那么把 `message` 误写成 `messages` 引起的 `KeyError` 会被 `except Exception` 吞掉——
程序只会一直显示"网络失败"，而真正的问题是一个字母。

> **兜底只兜不可控的外部故障；代码自己的 bug 必须让它炸出来。**

## 四、实测

| 场景 | 结果 |
|---|---|
| 正常调用 | 两轮出答案 ✅ |
| 域名写错 | `⚠ 网络请求失败：ConnectionError ...` + `任务中止` ✅ |
| 服务器返回空体 | `⚠ 网络请求失败：JSONDecodeError ...` ✅（瞬时空响应，重跑恢复） |

## 五、仍缺

- **失败后不重试**：一次瞬时抖动就会让整轮失败
- ~~`count_chars` 分支缺参数检查~~ → **已修**（补了 `if "text" in call["args"]`）。但**"每个工具都要手写一遍参数检查"的结构问题仍在**——工具多了必漏，解法是统一入口。
