# 心情助手 · 一个手写的多步 Agent

> 从零手写的一个命令行 Agent：能听懂自然语言、自己判断要不要调用工具、调完把结果带回来继续推理，并带有记忆与故障兜底。
>
> 不依赖任何 Agent 框架——**循环、工具分发、协议解析、保险，全部自己写**。

---

## 它是什么

一个跑在终端里的对话式智能体，主线能力是"记录并回看心情"，同时在过程中自主调用工具：

| 能力 | 说明 |
|---|---|
| **听懂人话** | 用户随便说一句，模型自己判断需不需要工具 |
| **自己选工具** | 可用工具：查今天日期、数字数、数字符数 |
| **多步执行** | 一个问题需要两次工具调用时，它会自己排顺序、分两轮做完 |
| **记得住** | 短期：保留最近 N 条对话；长期：启动时读回历史记录文件 |
| **不空转、不崩** | 六道保险：轮次上限、重复检测、未知工具、参数缺失、JSON 保护、超时 |

**实测样例**

```
$ python agent.py
[记录本] 2 条
[第 1 轮] 模型： {"tool":"get_today","args":{}}
   → 它想用工具： get_today
   → 工具返回： 2026-10-31
[第 2 轮] 模型： {"tool":"count_words","args":{"text":"今天是几号？顺便数数这句话有多少个字。"}}
   → 工具返回： 19
[第 3 轮] 模型： 今天是2026年10月31日。这句话共有19个字。
最终回答： 今天是2026年10月31日。这句话共有19个字。
```

## 架构

程序只有一个文件，四块结构：

```
① 三个工具函数      get_today() / count_words(text) / count_chars(text)
        ↓
② 通讯器 ask()      把整本记录本发给大模型，取回它的回话
        ↓
③ 记录本 messages   一个列表，每条是 {"role": ..., "content": ...}
        ↓
④ 主循环            for step in range(1, 4):
                      裁剪 → 问模型 → 判断是不是工具调用
                      → 剥出 tool/args → 执行 → 结果写回记录本 → 下一轮
```

**核心机制：模型不执行任何东西，它只输出"我要用哪个工具、参数是什么"；真正干活的是本地函数。**

协议走的是自定义 JSON：

```json
{"tool": "count_words", "args": {"text": "今天有点累"}}
```

这就是各家大模型 `function calling` 机制的手写版。

---

## 关键设计决策

| 决策 | 为什么 |
|---|---|
| **不用框架，手写循环** | 先把"循环 → 工具 → 回喂"这条链路走通，之后看任何框架都知道它在替自己做什么 |
| **自建 JSON 工具协议** | 比"回一个暗号词"能承载更多信息：要哪个工具 + 什么参数 |
| **指纹去重（工具名 + 参数）** | 只比工具名会误杀"连续查两天日期"这种合法操作 |
| **记忆并入 system，而非插成 user 消息** | 插成 `user` 时，模型会把它当成"要我处理的数据"，跑去统计字数（真实踩过） |
| **裁剪时永远保留 system** | system 里装着工具清单和输出格式，丢了它，模型就不再输出 JSON |
| **兜底时把错误当结果喂回去** | 模型看到"没有这个工具"才有机会改口；程序崩了就彻底没机会 |

## 踩过的坑（这部分比功能更有价值）

| 现象 | 根因 | 修复 |
|---|---|---|
| 连续三轮输出同一个工具调用，答案永远出不来 | 忘了把工具结果写回记录本，模型每轮都看到同样输入 | 加两条 `append` + 重复检测 |
| 问"我最近心情怎么样"，它却去统计历史记录的字数 | 记忆被塞成 `role:"user"`，被当成待处理数据 | 并入 system，并补一句"这是背景资料，不要统计它" |
| 模型调用了一个不存在的工具，程序 `UnboundLocalError` | 分发只有 if/elif，没有兜底分支 | 加 `else: result="没有这个工具"` |
| 模型输出少一个 `}`，程序整个崩掉 | `json.loads` 没被保护 | `try/except` + 打印原始输出 |
| 死循环跑了 54 万次才被 Ctrl+C 打断 | `while True` 没有出口 | 轮次上限 + `break` |
| 断网时程序直接抛 Traceback | `ask()` 没有网络异常兜底 | **尚未修复**（见下） |

## 如何运行

```bash
# 1. 安装依赖
pip install requests

# 2. 设置 API Key（不要写进代码）
# Windows CMD
set DEEPSEEK_API_KEY=sk-你的key
# PowerShell
$env:DEEPSEEK_API_KEY = "sk-你的key"

# 3. 运行（先把 agent.py 里的用户问题改成你想问的）
python agent.py
```

> **为什么用环境变量**：Key 写死在代码里，一旦代码上传或分享就会泄露。

## 已知限制（诚实清单）

| # | 问题 | 影响 |
|---|---|---|
| 1 | `count_chars` 分支缺参数检查 | 模型漏填 `text` → `KeyError` 崩溃 |
| 2 | `count_chars` 与 `count_words` 职责重叠 | 名字像、描述像，模型会选错且结果"看起来正常" |
| 3 | 网络失败后不重试，直接中止 | 一次瞬时抖动会导致整轮失败 |
| 4 | 轮次跑完无提示 | 达到上限后静默结束，用户以为它答完了 |
| 5 | 问题写死在代码里 | 一次运行只处理一个问题，还不是交互式 |
| 6 | 无 token 成本统计、日志不落盘 | 出问题无法回溯 |
| 7 | 长期记忆只做"全量塞"，没有检索 | 历史一长就会撑爆上下文 |
