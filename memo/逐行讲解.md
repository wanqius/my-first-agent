## 逐行讲解

### 第 1~2 行：借工具箱

```python
import os
import requests
```

**干嘛的**：从 Python 的"工具仓库"里，把两个工具箱搬进来用。

| 工具箱        | 里面装了什么       | 你用它干嘛                               |
| ---------- | ------------ | ----------------------------------- |
| `os`       | 跟操作系统打交道的小工具 | 用它的 `os.environ.get()` 读取环境变量里的 Key |
| `requests` | 专门负责"上网发请求"  | 用它给 DeepSeek 发消息                    |

**大白话**：相当于开工前先去仓库领两个工具箱。Python 自带几百个工具箱，不用全领，**用到哪个领哪个**。

---

### 第 4 行：跟用户打招呼

```python
print("你好，我是心情小助手。")
```

**干嘛的**：把引号里的话显示到屏幕上。

**大白话**：`print` = 打印/显示。引号里写什么，屏幕上就出什么。

---

### 第 6 行：接收你输入的话

```python
mood = input("今天心情怎么样？随便说说：")
```

**拆成两半看**：

| 部分             | 干嘛                             |
| -------------- | ------------------------------ |
| `input("...")` | 先显示引号里的话，然后**停下来等你打字**，等你按回车   |
| `mood = `      | 把你打的那串字，**装进一个叫 mood 的盒子**（变量） |

**大白话**：`input` = 发一张问卷并等你填；`mood =` = 给收上来的问卷贴个标签，方便后面引用。

**为什么要有 `mood` 这个盒子**：因为你后面还要用它两次（第 9 行存起来、第 19 行发给模型）。没名字就没法引用。

---

### 第 8~9 行：把心情存到文件

```python
with open("mood.txt", "a", encoding="utf-8") as f:
    f.write(mood + "\n")
```

**这行信息量最大，拆开看**：

| 部分                      | 干嘛                    | 大白话               |
| ----------------------- | --------------------- | ----------------- |
| `open("mood.txt", ...)` | 打开一个叫 mood.txt 的文件    | 拿出一个笔记本           |
| `"a"`                   | 打开方式 = **append（追加）** | 接着上次写，**不撕掉前面的**  |
| `encoding="utf-8"`      | 规定中文的存储编码             | 防止中文变乱码（写中文基本都要带） |
| `as f`                  | 给打开的文件起个短名字 `f`       | 给笔记本起外号，后面少打点字    |
| `with ... :`            | "用完自动关"的写法            | 写完自动合上笔记本，不用手动关   |
| `f.write(...)`          | 往文件里写内容               | 在笔记本上落笔           |
| `mood + "\n"`           | 你输入的内容 + 一个换行符        | 写完换行，不然两次记录会挤在一行  |

**关键点**：`"a"` 写成了 `"w"` 会怎样？**每次运行都清空重写**——你之前的历史就没了。这就是"追加"和"覆盖"的区别，是文件操作最常见的坑。

---

### 第 11~12 行：把历史读回来

```python
with open("mood.txt", "r", encoding="utf-8") as f:
    history = f.read()
```

| 部分           | 干嘛                          |
| ------------ | --------------------------- |
| `"r"`        | 打开方式 = **read（只读）**，这次是翻开来看 |
| `f.read()`   | **一次性读完整个文件**，返回一整段文字       |
| `history = ` | 装进叫 history 的盒子             |

**这就是"记忆"的实现**：把过去所有记录读出来，装进 `history`。

> 对比：上次学过的 `f.readlines()` 是读成"一排格子"（每行一个），`f.read()` 是读成"一整块文字"。这里不需要分行，所以用 `read()` 更直接。

---

### 第 14~21 行：把话发给大模型

```python
response = requests.post(
    "https://api.deepseek.com/chat/completions",
    headers={"Authorization": "Bearer " + os.environ.get("DEEPSEEK_API_KEY", "")},
    json={
        "model": "deepseek-chat",
        "messages": [{"role": "user", "content": "我最近的心情记录：\n" + history + "\n请用一句话回应我，不超过25字。"}],
    },
)
```

**这三块参数，对应"寄一封信"的三件事**：

| 参数         | 是什么                                         | 大白话                                                                |
| ---------- | ------------------------------------------- | ------------------------------------------------------------------ |
| 第 1 个：网址   | `https://api.deepseek.com/chat/completions` | **信封上的地址**——信寄到 DeepSeek 的"对话服务"窗口                                 |
| `headers=` | 请求头                                         | **信封上贴的通行证**，里面那张 `Authorization: Bearer sk-xxx` 就是你的 Key，证明"是我本人" |
| `json=`    | 信的内容                                        | **信纸**，里面告诉它：用哪个模型、说什么话                                            |

**再拆 `json=` 里面的东西**：

| 键            | 值                 | 说明                                               |
| ------------ | ----------------- | ------------------------------------------------ |
| `"model"`    | `"deepseek-chat"` | 选用哪个模型（DeepSeek 有好几款）                            |
| `"messages"` | 一个列表              | 对话内容。`"role": "user"` = 这轮是"用户说的"，`content` 才是正文 |

**你写的 prompt 长这样**（第 19 行拆开）：

```
我最近的心情记录：
<history 里的一大段历史>
请用一句话回应我，不超过25字。
```

**大白话**：把"你的历史 + 这次的要求"打包成一封信，寄出去。`response =` 就是"等回信，把回信装进盒子"。

---

### 第 22 行：从回信里挑出正文

```python
print(response.json()["choices"][0]["message"]["content"])
```

**这行最吓人，其实是在"剥洋葱"**——模型的回信是一大坨结构化数据，得一层层剥：

| 层级                | 剥出什么                  | 大白话         |
| ----------------- | --------------------- | ----------- |
| `response.json()` | 把回信从"一坨文字"变成"可查的数据"   | 拆信封         |
| `["choices"]`     | 里面装着"所有候选回复"（通常是 1 个） | 翻到"备选回答"那叠纸 |
| `[0]`             | 取**第 0 个**（就是第一个）     | 拿最上面那张      |
| `["message"]`     | 这张纸里的"消息"部分           | 看清是"消息"栏目   |
| `["content"]`     | 消息里的**正文文字**          | 读正文         |
| 最外层 `print(...)`  | 显示出来                  | 念给你听        |

**一句话总结**：`response.json()["choices"][0]["message"]["content"]` = **"从模型回信里，把真正的回答文字取出来"**。

> **这是最值得记住的一行**。因为你以后调任何模型（OpenAI、千问、豆包），这一串结构几乎一样，只是模型名和地址不同。

## 你问的第二个问题：这些都要懂吗？

**答案：分清三类——必须懂、要能看懂、可以完全交给 AI。**

| 代码                                     | 类别            | 原因                          |
| -------------------------------------- | ------------- | --------------------------- |
| `print` / `input` / 变量                 | ✅ **必须懂**     | 这是最基本的"程序与人对话"，一分钟就能学会      |
| `open` / `write` / `read`              | ✅ **必须懂**     | 数据存取是智能体的"记忆"，不懂就不知道记忆怎么来的  |
| `requests.post` 的结构                    | ✅ **必须懂**     | 调模型是智能体的核心动作，**每个智能体都要写这段** |
| `os.environ.get` 读 Key                 | ✅ **必须懂**     | 涉及安全，Key 泄露是真事故             |
| `["choices"][0]["message"]["content"]` | ⚠️ **要能看懂**   | 记住"这是剥洋葱取正文"就够了，不用背         |
| `with ... as f` 的写法                    | ⚠️ **要能看懂**   | 知道"用完自动关"即可，细节可以查           |
| `encoding="utf-8"`                     | ⚠️ **要能看懂**   | 知道"防中文乱码"就够了                |
| 复杂的类型转换、异常处理细节                         | ⭕ **可以交给 AI** | 用到了现查现学                     |

### 核心结论（这句话你记住就够）

> **要懂的，不是"所有代码"，而是这三样：**
>
> 1. **数据从哪进来**（`input`）
> 2. **数据存到哪去**（`open` / `write` / `read`）
> 3. **模型怎么被调用**（`requests.post` 那一段）

**这三件事，是所有智能体的共同骨架。** 剩下那些"语法细节"（怎么拼字符串更优雅、异常怎么写得漂亮），AI 写得比你快，**你需要的是知道它在干嘛、判断它写得对不对**——这就是你的路线里说的"读懂 / 跑改 / 指挥"。

> **换个角度说**：你现在这 22 行，已经是"智能体最小完整骨架"了。以后不管你用 LangChain 还是别的框架，**框架帮你封装掉的，就是这些底层的活**。**懂了底层再看框架，就是"我知道它在替我做什么"；不懂底层直接用框架，就是"它坏了我也没办法"。**

## 第 8~11 行：拦住"空输入"

```python
if mood.strip() == "":
    print("你还没说话呢，下次再来。")
    exit()
````

| 部分             | 干嘛                 | 大白话                        |
| -------------- | ------------------ | -------------------------- |
| `mood.strip()` | 把内容**头尾的空格、换行都去掉** | 相当于"擦掉纸上的空白"——只敲空格的人，等于没说话 |
| `== ""`        | 判断"是不是等于空"         | 问"这张纸是白的吗？"                |
| `if`           | "如果……就……"          | 条件成立才执行下面的缩进行              |
| `exit()`       | **让程序立刻结束**        | 不往下走了，收工                   |

**为什么不能省掉 `strip()`**：如果只写 `if mood == ""`，那用户敲了 3 个空格，程序会认为"他说了话"，然后记一条全是空格的脏数据。

**这是"提前退出"（fail fast）的第一个例子**：与其让坏数据流下去，不如在门口就拦住。

## 第 14~17 行：提前检查 Key

```python
key = os.environ.get("DEEPSEEK_API_KEY", "")
if key == "":
    print("没找到 API Key。请先在命令行设置：set DEEPSEEK_API_KEY=sk-你的key")

```

| 部分                                       | 干嘛              | 大白话                    |
| ---------------------------------------- | --------------- | ---------------------- |
| `os.environ.get("DEEPSEEK_API_KEY", "")` | 从**环境变量**里读 Key | 查看"系统里有没有存这个钥匙"        |
| `, ""` （第二个参数）                           | **读不到时的默认值**    | "如果找不到，就当它是空字符串"，而不是报错 |
| `key = `                                 | 存进 `key` 盒子     | 后面第 29 行要用             |

**关键改动**：v1 是直接在 `headers` 里现读现用；v2 是**先读出来存进 `key`，检查通过才往下走**。

**为什么这样更好**：v1 那样写，Key 是错的也要走完全程直到撞墙；v2 在**第 15 行就拦住**，还顺便告诉用户**怎么解决**（给出设置命令）。这就是从"崩溃"到"友好提示"的差别。

## 第 26 行 / 第 43~44 行：`try` 与 `except`

```python
try:
    ...（第 27~41 行）
except Exception as e:
    print("出问题了：", type(e).__name__, e)
```

**`try:` 开头的这一段，是"重灾区"** —— 从第 27 行发请求到第 41 行打印答案，全都包在里面。

| 部分                       | 干嘛                               | 大白话                            |
| ------------------------ | -------------------------------- | ------------------------------ |
| `try:`                   | **"试着做下面这些事"**                   | 有护栏的桥，允许掉下去                    |
| 缩进的整块                    | 要保护起来的代码                         | 桥面上走的那段路                       |
| `except Exception as e:` | **"万一任何错误发生，走这里"**               | 桥下的兜底网；`as e` = 把错误详情装进 `e` 盒子 |
| `Exception`              | "几乎所有的错误类型"                      | 不挑种类，一律接住                      |
| `type(e).__name__`       | 取出错误的**名字**（如 `ConnectionError`） | 问"你摔倒的原因叫什么"                   |
| `e`                      | 错误的具体描述                          | 问"具体是什么情况"                     |

**大白话总结**：

```
try:      →  "我试着过桥"
except:   →  "万一摔了，我用这张网接住，并且告诉你摔在哪儿"
```

**为什么 `try` 要包这么一大块**（27~41 行），而不是只包第 27 行？

因为**这整段都是"依赖外部"的**——发请求（可能断网）、解析 JSON（可能格式不对）、翻 `choices`（可能没这个字段）。**它们是一条链，一环断了后面全废**，所以一起保护。

> 对比第 9 行、第 15 行的 `if` 判断——**那些是"自己能控制的"，不需要 try**。  
> **规律：只有"你控制不了的意外"才需要 try。** 这也是我上节课说的"try 范围要小"。

## 第 36~41 行：检查回信是不是"坏消息"


```python
data = response.json()

if "error" in data:
    print("模型说：", data["error"]["message"])
else:
    print(data["choices"][0]["message"]["content"])
```

| 部分                         | 干嘛                         | 大白话         |
| -------------------------- | -------------------------- | ----------- |
| `data = response.json()`   | 把回信解析出来，存进 `data`          | 拆信封，先把内容放桌上 |
| `if "error" in data:`      | **问"这封信里有没有 `error` 这个词"** | 先看是不是坏消息    |
| `data["error"]["message"]` | 取出错误的原话                    | 把坏消息读出来     |
| `else:`                    | 不是坏消息，那就是好消息               | 走另一条路       |
| `data["choices"][0]...`    | 剥洋葱取正文（v1 讲过）              | 读正常回信       |

**这是 v2 最值钱的一处改动**。

回想你上节课的崩溃：`KeyError: 'choices'`——因为当时**没检查就直接翻**，回信里只有 `error` 没有 `choices`，所以扑空。

现在**先分类、再拆**：

- 有 `error` → 走"读错误"这条路
- 没有 → 走"读正文"这条路

**这个模式在企业里非常常见**，叫"**先校验，再消费**"——处理任何外部来的数据（API 回信、用户上传、文件读取），都先检查格式对不对，再决定怎么用。

## v2 的已知不足（诚实记录）

| 不足              | 现状                                       | 以后怎么改            |
| --------------- | ---------------------------------------- | ---------------- |
| 错误不分类           | `except Exception` 一网打尽，超时/限流/余额不足都提示同一句 | 按错误类型分别处理        |
| 无重试             | 网络抖一下就直接放弃                               | 加"失败重试 2 次"逻辑    |
| 无日志             | 出错只打印在屏幕上，关了窗口就没了                        | 错误写进 `error.log` |
| `mood.txt` 无限增长 | 记录越多，发给模型的内容越长、越贵                        | 只取最近 N 条         |
